# conditions_info — Methoden-Doku

## Klassenueberblick
`conditions_info` ist die statische Discovery-/Form-Fassade fuer Regel-Bedingungen (Conditions). Sie findet alle verfuegbaren Condition-Klassen per Filesystem-`glob` ueber `classes/booking_rules/conditions/*.php` plus per Namespace-Scan ueber alle installierten `bookingextension`-Subplugins, instanziiert sie und baut den Condition-Teil des Regel-mform (Dropdown plus dynamischer No-Submit-Button zum Nachladen der gewaehlten Condition-Felder). Keine eigene Persistenz. Kollaborateure: `$CFG`, `glob`/`pathinfo`, `core_plugin_manager`, `core_component`, `MoodleQuickForm`, das Interface `booking_rule_condition` (jede Condition implementiert `get_name_of_condition`, `can_be_combined_with_bookingruletype`, `add_condition_to_mform`).

## Methoden

### `public static function add_conditions_to_mform(MoodleQuickForm &$mform, ?array &$ajaxformdata = null)` — public static
- **Zweck:** Fuegt dem Regelformular den Condition-Auswahl-Block hinzu: ein Select mit allen (mit dem aktuellen `bookingruletype` kombinierbaren) Conditions, einen versteckten No-Submit-Button zum AJAX-Nachladen, und ruft `add_condition_to_mform` der aktuell gewaehlten Condition fuer deren Detailfelder. **Seiteneffekte:** `self::get_conditions()` (instanziiert ALLE Conditions), liest `$ajaxformdata['bookingruletype']`/`['bookingruleconditiontype']`, mutiert `$mform` (Select, Submit, Type). Bei fehlender Vorauswahl wird die erste Condition via Destructuring `[$condition] = $conditions` genommen. **Rueckgabe:** void. **Bewertung:** B — Filterung per `can_be_combined_with_bookingruletype` korrekt; `[$condition] = $conditions` setzt voraus, dass `get_conditions()` nie leer ist (sonst Notice/Fehler) — fuer das ausgelieferte Plugin immer erfuellt.

### `public static function get_conditions()` — public static
- **Zweck:** Liefert je eine Instanz aller verfuegbaren Condition-Klassen (Kern-Conditions per Verzeichnis-Scan plus Conditions aus `bookingextension_*`-Subplugins). **Seiteneffekte:** `glob($CFG->dirroot . '/mod/booking/classes/booking_rules/conditions/*.php')`, `pathinfo`, `class_exists` und `new $classname()` je Treffer; `core_plugin_manager::instance()->get_plugins_of_type('bookingextension')` plus `core_component::get_component_classes_in_namespace(..., 'rules\\conditions')`. **Rueckgabe:** Array von Condition-Instanzen. **Bewertung:** B — Klassennamen-aus-Dateinamen-Konvention ist fragil aber etabliert; `glob` + Instanziierung bei jedem Aufruf ist nicht gecacht (mehrfaches Newing pro Form-Render), fuer einen Admin-Form-Pfad vertretbar.

### `public static function get_condition(string $conditionname)` — public static
- **Zweck:** Instanziiert genau eine Condition anhand ihres Kurznamens (zuerst Kern-Namespace, dann pro `bookingextension`-Subplugin). **Seiteneffekte:** `class_exists` + `new`; `core_plugin_manager::instance()->get_plugins_of_type('bookingextension')`-Iteration fuer den Extension-Fall. **Rueckgabe:** Condition-Instanz oder `null`, wenn der Name nirgends matcht. **Bewertung:** B — `$conditionname` kommt aus Formdaten und wird ungeprueft an den Klassennamen konkateniert; durch das vorgeschaltete `class_exists` auf den festen Namespace-Praefix ist nur das Instanziieren existierender Klassen in `mod_booking\booking_rules\conditions\*` bzw. `bookingextension_*\rules\conditions\*` moeglich (kein beliebiger Class-Load) — akzeptabel. Rueckgabe `null` muss vom Aufrufer behandelt werden (in `add_conditions_to_mform` wird sie ungeprueft dereferenziert -> potenzielle Fehlerquelle bei manipuliertem `bookingruleconditiontype`).

## Bewertungs-Resümee
Sauberes, erweiterbares Discovery-Pattern (Verzeichnis-Scan plus Subplugin-Namespace-Scan) mit konsequentem `class_exists`-Gating. Schwaechen: wiederholtes ungecachtes Instanziieren aller Conditions pro Render, und die in `add_conditions_to_mform` ungeprueft dereferenzierte Rueckgabe von `get_condition` (manipulierter `bookingruleconditiontype` -> Aufruf auf `null`). Funktional weitgehend unkritisch. Klassen-Score **B / P2**.
