## Klassenueberblick
`placeholders_info` ist die zentrale Substitutions-Engine fuer Booking-Texte (Mails, Beschreibungen, Pollurls). Sie erkennt `{token}`-Platzhalter per Regex, dispatcht sie an die passende Platzhalterklasse (aus `mod_booking\placeholders\placeholders\` oder einem `bookingextension_*`-Namespace), ersetzt sie durch deren `return_value()`, und verarbeitet Mustache-aehnliche Abschnitte (`{#name}...{/name}`), die bei leerem Wert geloescht werden. Zwei statische Caches halten Zustand ueber die Request-TTL: `$placeholders` (Wert-Cache, von den Platzhalterklassen befuellt) und `$localizedplaceholders` (lokalisierte Auswahlliste). Kollaborateure: `core_component`/`core_plugin_manager` (Klassen-Discovery), `customfields` (Sonderbehandlung Custom-Felder), `html_writer`, `$USER`, `get_string`. Keine eigene DB-/Tabellen-Persistenz.

## Methoden

### `public static function render_text(string $text, int $cmid = 0, int $optionid = 0, int $userid = 0, int $installmentnr = 0, int $duedate = 0, float $price = 0, int $descriptionparam = MOD_BOOKING_DESCRIPTION_WEBSITE, ?string $rulejson = null, $pollurl = false)` — public static
- **Zweck:** Hauptpfad: dekodiert URL-kodierte Klammern (`%7B`/`%7D`), extrahiert alle Token via `preg_match_all('/{(?!mlang\b)(?!mlang\s)(.*?)}/', ...)` (mlang-Tags ausgenommen), faellt `$userid` auf `$USER->id` zurueck, sucht je Token die Klasse ueber die Namespace-Liste (Core + alle `bookingextension`-Plugins), respektiert `for_pollurl()` im Pollurl-Modus, ruft `return_value(...)` per Referenz auf `$text`/`$placeholders` auf, behandelt Array-Rueckgaben (indexiert via Zahl im Token, sonst `reset()`) und ersetzt das Token. Unbekannte Tokens werden bei vorhandener `$optionid` an `customfields::return_value(...)` weitergereicht. Ein zweiter Durchlauf raeumt Abschnitts-Marker (`#`/`/`) auf: leere Abschnitte werden inkl. Inhalt geloescht, gefuellte nur ihrer Marker entledigt. **Seiteneffekte:** ruft `return_list_of_placeholders()` (befuellt `$localizedplaceholders`), liest `$USER`, mutiert lokale `$text`-Kopie; ueber `return_value`-Aufrufe potenziell DB-/Cache-Zugriffe der Platzhalterklassen. **Rueckgabe:** der substituierte Text (kein deklarierter Typ). **Bewertung:** C — funktional maechtig, aber fragil: (1) `$value` wird im Token-Loop **nicht je Iteration initialisiert**; existiert die Klasse nicht UND ist `$optionid` leer, bleibt `$value` der Wert der Vorgaenger-Iteration und wird bei `if (!empty($value))` faelschlich erneut eingesetzt (Daten-/Render-Bug). (2) Der Leer-Abschnitts-Zweig setzt bei nicht gefundenem `$end` das Pattern `'/\$\{placeholder\}/'` — ein literales, faktisch nie matchendes Regex (offenkundiger Tippfehler statt `preg_quote('{'.$placeholder.'}')`), sodass leere Abschnitte ohne Endmarker nicht entfernt werden. (3) Doppelter `str_replace` desselben Tokens (im Klassen-Zweig und erneut bei `!empty($value)`) ist redundant. (4) Die innere `foreach ($placeholders as $index => $ph)` klobbert die `$index`-Variable der aeusseren Schleife. (5) Lineare Klassen-Suche pro Token ist O(Tokens × Namespaces), fuer typische Textmengen unkritisch.

### `public static function return_list_of_placeholders($pollurl = false): string` — public static
- **Zweck:** Baut (einmalig, lazy) die lokalisierte Platzhalterliste und rendert sie als `<ul class="booking-placeholders">` mit `<li data-id=...>{token} Label</li>`-Eintraegen fuer die Editor-UI. **Seiteneffekte:** ruft `create_list_of_localized_placeholders($pollurl)`, das `self::$localizedplaceholders` befuellt. **Rueckgabe:** HTML-`string`. **Bewertung:** B — sauber; Vorbehalt: der `$pollurl`-Parameter beeinflusst nur den **ersten** Aufbau (danach greift der Cache), sodass ein spaeterer Aufruf mit anderem `$pollurl` die einmal gebaute Liste unveraendert zurueckgibt (TTL-Caching-Annahme).

### `private static function create_list_of_localized_placeholders($pollurl = false)` — private static
- **Zweck:** Sammelt via `core_component::get_component_classes_in_namespace` alle Core- und `bookingextension`-Platzhalterklassen, filtert nach `is_applicable()` (und `for_pollurl()` im Pollurl-Modus), behandelt `customfields` als Sonderfall (Label aus `customfields::return_placeholder_text()`) und baut die Map `lokalisierter Name => Klassenname`. **Seiteneffekte:** schreibt `self::$localizedplaceholders` (Request-Cache); `get_string` je Klasse. **Rueckgabe:** `array|void` — gibt bei bereits gefuelltem Cache fruh zurueck, sonst die Map. **Bewertung:** B — Discovery korrekt; doppelte „bereits gebaut"-Guard (auch in `return_list_of_placeholders`); `get_string($class, $component)` ohne `string_exists`-Pruefung wirft bei fehlendem Sprachstring (debugging), was bei unvollstaendig lokalisierten Extension-Platzhaltern auffaellt.

### Triviale Properties
Zwei oeffentliche statische Caches (`$placeholders`, `$localizedplaceholders`, Z.49/54) als request-weite Werte-Halter ohne Kapselung.

## Bewertungs-Resümee
Funktionale Kern-Engine des Messaging-Subsystems mit hoher Verantwortung. Discovery, Dispatch und Caching sind solide, doch der Token-Loop traegt zwei echte Defekte (nicht zuruecksetztes `$value` ueber Iterationen; totes Loesch-Regex `'/\$\{placeholder\}/'`) und mehrere Fragilitaeten (Variablen-Klobbering, redundante Ersetzungen, `$pollurl`-cache-blind). Funktional meist tolerierbar, in Randfaellen jedoch fehl-substituierend bzw. nicht aufraeumend. Klassen-Score **C / P2**.
