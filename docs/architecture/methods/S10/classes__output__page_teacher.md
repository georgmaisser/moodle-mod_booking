# page_teacher — Methoden-Doku

## Klassenueberblick
`page_teacher` ist das renderable/templatable DTO der oeffentlichen Lehrenden-Profilseite (`teacher.php`). Der Konstruktor validiert, dass die teacherid existiert *und* tatsaechlich in `booking_teachers` als Lehrkraft gefuehrt ist; bei Fehlschlag wird ein Fehlerzustand gesetzt. `export_for_template()` baut Stammdaten, Beschreibung (pluginfile-rewritten), Profilbild, E-Mail/Telefon (unter Capability/Sichtbarkeitsregeln) und vor allem die pro Buchungsinstanz gruppierten Options-Tabellen des Lehrenden. Persistenz: keine eigene. Kollaborateure: `$DB`, `$PAGE`/`$USER`/`$CFG`, `singleton_service`, `view` (wunderbyte_table-Render), `booking_answers`, `\user_picture`, `get_fast_modinfo`, `local_musi`-Sonderpfad, `booking_semesters` (Sortierung).

## Methoden

### `public function __construct(int $teacherid)` — public
- **Zweck:** Laedt den `user`-Record des Lehrenden und prueft, ob die id in `SELECT DISTINCT userid FROM {booking_teachers}` vorkommt. Setzt bei Nichtfinden `error`/`errormessage` (Strings `teachernotfound` bzw. `notateacher`). **Seiteneffekte:** `$DB->get_record('user', ...)`, `$DB->get_records_sql($sqlteachers)`. **Bewertung:** C — **Undefined-Variable-Risiko:** `$teacherids` wird nur innerhalb von `if ($teacherrecords = ...)` befuellt. Existiert *gar keine* Zeile in `booking_teachers`, ist `$teacherids` beim `in_array($teacherid, $teacherids)` undefiniert → PHP-Warning und (in PHP 8) `in_array($x, null)`-TypeError-Risiko. Pragmatisch tritt das selten auf, ist aber ein echter Defekt. Zudem laedt die Methode die komplette Teacher-Liste nur, um eine Mitgliedschaft zu pruefen — `$DB->record_exists('booking_teachers', ['userid' => $teacherid])` waere direkt.

### `public function export_for_template(renderer_base $output)` — public
- **Zweck:** Liefert bei Fehlerzustand `{error, errormessage}`; sonst das volle Profil-Array: `teacher` (Name, pluginfile-rewritten + `format_text`-Beschreibung, `optiontables`, `canedit`), optional `email` (Sichtbarkeitskaskade identisch zu `page_allteachers`), Profilbild, Messaging-Flag, Telefonnummern (nur mit `seepersonalteacherinformation`), Link zum „performed units"-Report (nur mit `updatebooking`), `wwwroot`. **Seiteneffekte:** `context_user::instance(...,MUST_EXIST)`, `file_rewrite_pluginfile_urls`, `format_text`, `new \user_picture`, `has_capability`-Checks (gemischt gegen `$context` = user-context bzw. `$PAGE->context`), `booking_answers::number_actively_booked`, `self::teacher_messaging_is_possible`, Delegation an `get_option_tables_for_teacher`. **Rueckgabe:** Render-Array. **Bewertung:** B — korrekt und gut kommentiert; die E-Mail-Sichtbarkeit prueft `mod/booking:updatebooking` hier gegen den *User-Context* des Lehrenden (in `page_allteachers` gegen System-Context) — leicht inkonsistente Capability-Semantik.

### `private function get_option_tables_for_teacher(int $teacherid, $perpage = 100)` — private
- **Zweck:** Ermittelt alle Buchungsinstanzen, in denen der Lehrende unterrichtet, sortiert sie (Semester-Startdatum DESC, sonst bookingid DESC) und rendert pro sichtbarer Instanz eine wunderbyte_table mit den Optionen des Lehrenden; erste Tabelle eager, restliche lazy. **Seiteneffekte:** `$DB->get_records_sql(...)` (JOIN booking/booking_semesters); optionaler `local_musi`-Sonderpfad (`get_config('local_musi','shortcodessetinstance')`, hebt eine Instanz nach vorne); `get_config('booking','teacherpageshiddenbookingids')`-Filter; pro Instanz `singleton_service::get_instance_of_booking_by_bookingid`, `get_fast_modinfo($booking->course, $USER->id)` + `get_cm`, `new view(...)->get_rendered_table_for_teacher(...)`. **Rueckgabe:** Array von Tabellen-Descriptoren (`bookingid`, `bookinginstancename`, `tablename`, `table`-HTML, `class`). **Bewertung:** C — mehrere echte Schwaechen: (a) **N+1**: pro Buchungsinstanz je ein `get_fast_modinfo`- und ein `view`-Render-Roundtrip in der Schleife; (b) **`explode`-Falle**: `explode(',', get_config(...) ?? '')` liefert bei leerem Setting `['']`, sodass `!empty($hiddenbookingids)` *immer* true ist und die Filter-Schleife stets laeuft (harmlos, da `in_array(int, [''])` nicht matcht, aber irrefuehrend); (c) **Dead Code**: der `if (1 == 2)`-Block (Z.279) ist absichtlich toter Code mit TODO. `$perpage` wird entgegen Signatur nie verwendet.

### `public static function teacher_messaging_is_possible(int $teacherid)` — public static
- **Zweck:** Prueft, ob der eingeloggte `$USER` und der Lehrende mindestens einen gemeinsamen Kurs (via aktive `user_enrolments`) teilen — Moodle-Voraussetzung fuers Messaging. **Seiteneffekte:** `$DB->get_records_sql($sql, $params)` mit einem `INTERSECT` zweier Enrolment-Selects. **Rueckgabe:** `bool`. **Bewertung:** C — **Portabilitaet:** `INTERSECT` ist nicht in allen von Moodle unterstuetzten DB-Engines/Versionen verfuegbar (aeltere MySQL/MariaDB-Versionen kennen es nicht); ein `EXISTS`/`JOIN`-Konstrukt waere portabler. Wird zudem pro Lehrperson in Listen-Kontexten aufgerufen (Per-Zeilen-Query).

## Bewertungs-Resümee
Funktional vollstaendiges Profil-DTO mit sauberer Sichtbarkeitslogik und durchdachter Lazy-Tabellen-Strategie. Belastet durch das Undefined-`$teacherids`-Risiko im Konstruktor, N+1 in `get_option_tables_for_teacher`, die `explode`-`['']`-Falle, die `INTERSECT`-Portabilitaetsfrage und etwas inkonsistente Capability-Contexts. Kein Datenverlust, aber Robustheits- und Performance-Reserven. Klassen-Score **B / P3**.
