## Klassenueberblick
`slot_price` ist eine zustandslose Service-Klasse (nur statische Methoden) zur Berechnung von Slot-Buchungspreisen. Sie kombiniert den per `mod_booking\price` aufgeloesten Standard-Optionspreis (preiskategorie-abhaengig pro User) mit den Slot-Preisregeln aus `slot_rules` (`apply_price_rules_to_slot_price`). Kern ist ein lasttragender Fallback: wenn `mod_booking\price::get_price()` fuer die aufgeloeste Preiskategorie keine Zeile findet (z.B. `pricecategoryfallback` auf leere Kategorie oder Option ohne `default`-Preiszeile), wird der Basispreis direkt aus den Preiszeilen der Option (`get_prices_from_cache_or_db`) ermittelt. Keine eigene Persistenz. Kollaborateure: `mod_booking\price`, `singleton_service` (User-Aufloesung), `slot_rules` (Regelanwendung). Konsumenten: `target_price_policy`, Slot-Booking-/Rebooking-Pfade.

## Methoden

### `public static function calculate_slot_price_data(int $optionid, int $slotstart, int $slotend, int $userid = 0): array` — public static
- **Zweck:** Liefert das vollstaendige Preis-Datenpaket (`price`, `currency`, `pricecategoryidentifier`) fuer genau einen Slot; startet vom Basispreis und wendet die zeit-/regelabhaengigen Slot-Preisregeln an. **Seiteneffekte:** keine (delegiert lesend an `get_base_slot_price_data` und `slot_rules::apply_price_rules_to_slot_price`). **Rueckgabe:** Array mit `price` (auf 2 Dezimalen gerundet), `currency`, `pricecategoryidentifier`. Bei ungueltigem Zeitfenster (`slotstart <= 0` oder `slotend <= slotstart`) wird der unmodifizierte Basisdatensatz zurueckgegeben (keine Regelanwendung). **Bewertung:** A — klarer Guard, defensive Casts, Regelanwendung sauber gekapselt.

### `public static function calculate_price(int $optionid, int $numslots, int $userid = 0, array $slots = []): float` — public static
- **Zweck:** Gesamtpreis fuer mehrere Slots. Ohne konkrete Slot-Liste wird linear `Basispreis * numslots` gerechnet; mit Slot-Liste wird pro gueltigem Slot `calculate_slot_price_data` summiert (also inkl. Preisregeln). **Seiteneffekte:** keine direkten; bei nichtleerer `$slots`-Liste ein `get_base_slot_price_data`-Aufruf plus ein weiterer pro Slot (siehe Bewertung). **Rueckgabe:** gerundeter Gesamtpreis (`0.0` bei `numslots <= 0`). **Bewertung:** B — funktional korrekt, aber zwei Punkte: (1) der `empty($slots)`-Pfad ueberspringt Preisregeln bewusst (kein Zeitfenster zur Regelauswertung vorhanden) und kann daher von der Summe der Einzel-Slot-Preise abweichen — beabsichtigte, aber leicht ueberraschende Asymmetrie; (2) `get_base_slot_price_data` wird einmal direkt und dann erneut innerhalb jedes `calculate_slot_price_data`-Aufrufs ausgefuehrt (der direkte Aufruf in Z.80–82 ist im Slot-Pfad ungenutzt — `$basepriceperslot`/`$pricecategoryidentifier` werden dort nicht verwendet).

### `private static function get_base_slot_price_data(int $optionid, int $userid = 0): array` — private static
- **Zweck:** Ermittelt den Basispreis pro Slot. Primaerweg: `mod_booking\price::get_price('option', $optionid, $user)` (User-spezifische Kategorie). Fallback bei leerem/leerstring-Preis: direkte Aufloesung ueber die Preiszeilen der Option — bevorzugt die `default`-Kategorie, sonst die erste Zeile. **Seiteneffekte:** `singleton_service::get_instance_of_user($userid)` nur bei `userid > 0`; `mod_booking\price::get_price` und ggf. `get_prices_from_cache_or_db` (Cache/DB-Lesezugriff). **Rueckgabe:** Array `price`/`currency`/`pricecategoryidentifier`; bei voelliger Preislosigkeit `['price'=>0.0,'currency'=>'','pricecategoryidentifier'=>'default']`. **Bewertung:** B — der Fallback ist explizit als lasttragend dokumentiert und testabgedeckt (`slot_price_test::test_fallback_provides_base_price_when_resolver_empty`); `pricecategoryidentifier` kann eine kommaseparierte Liste sein, die hier per `explode(',')`/`in_array('default', ...)` korrekt geprueft, aber im Rueckgabewert als Rohstring (inkl. Kommas) durchgereicht wird.

## Bewertungs-Resümee
Saubere, testabgedeckte Preisberechnung mit bewusstem, dokumentiertem Fallback gegen die Leer-Aufloesung von `mod_booking\price`. Schwaechen sind nicht funktionskritisch: die Asymmetrie zwischen dem `empty($slots)`-Linearpfad und dem regelbasierten Summenpfad sowie die ungenutzten lokalen Variablen im Slot-Pfad von `calculate_price`. Klassen-Score **B / P3**.
