## Klassenueberblick
`actions` ist eine Optionfeld-Klasse (`extends field_base`) im Field-Plugin-System der Buchungsoption. Sie kapselt das Feld „Booking-Actions" (nutzerdefinierte Folgeaktionen einer Buchungsoption, z.B. Weiterleitung/Verknuepfung) und ist als `MOD_BOOKING_EXECUTION_POSTSAVE` markiert — wird also erst nach Anlegen der Option (wenn die optionid vorliegt) verarbeitet. Persistenz: Das Feld hat keine eigene DB-Spalte, sondern wird als JSON-Fragment unter dem Schluessel `boactions` im `json`-Feld der Buchungsoption abgelegt (via `booking_option::add_data_to_json` / `get_value_of_json_by_key`). Kollaborateure: `mod_booking\bo_actions\actions_info` (Formularaufbau der einzelnen Actions), `booking_option` (JSON-Persistenz), `field_base` (Basisklasse), `MoodleQuickForm`. Die Klasse ist rein statisch (alle Methoden static), Zustand liegt ausschliesslich in den Konfig-Properties.

## Methoden

### `public static function prepare_save_field(stdClass &$formdata, stdClass &$newoption, int $updateparam, $returnvalue = null): array` — public static
- **Zweck:** Uebernimmt die im Formular gewaehlten Booking-Actions aus den Formulardaten in das zu speichernde Optionobjekt — speichert hier nicht direkt, sondern haengt das JSON-Fragment an. Liest bevorzugt `$formdata->boactionsjson` (JSON-String aus dem Form-Workflow) und decodiert es; faellt sonst auf `$formdata->boactions ?? []` zurueck. Schreibt das Ergebnis via `booking_option::add_data_to_json($newoption, 'boactions', $boactions)` in den `json`-Aufbau von `$newoption`. **Seiteneffekte:** mutiert `$newoption` (per Referenz). **Rueckgabe:** `array` — immer leer (keine Warnungen). **Bewertung:** B — korrekt und kommentiert; die Signatur deklariert `$updateparam`/`$returnvalue`, beide werden im Body nicht genutzt (Interface-Konformitaet mit `field_base`). `json_decode` ohne Fehlerpruefung: bei korruptem `boactionsjson` wird `null` an `add_data_to_json` durchgereicht — in der Praxis vom Form-Workflow kontrolliert befuellt, daher geringes Risiko.

### `public static function instance_form_definition(MoodleQuickForm &$mform, array &$formdata, array $optionformconfig, $fieldstoinstanciate = [], $applyheader = true)` — public static
- **Zweck:** Fuegt die Formularelemente fuer Booking-Actions ins Optionsformular ein, indem es an `actions_info::add_actions_to_mform($mform, $formdata)` delegiert. **Seiteneffekte:** mutiert `$mform`. **Rueckgabe:** `void`. **Bewertung:** B — duenne Delegation; die Parameter `$optionformconfig`, `$fieldstoinstanciate`, `$applyheader` werden ignoriert (Signatur-Konformitaet mit der Field-API). Der Kommentar „Actions are not yet finished - so we hide them for now" deutet auf Feature-in-Arbeit hin; das Verstecken/Header-Handling liegt offenbar in `add_actions_to_mform`, nicht hier.

### `public static function set_data(stdClass &$data, booking_option_settings $settings)` — public static
- **Zweck:** Ueberfuehrt den gespeicherten Wert zurueck ins Formular. Beim Import (`$data->importing` gesetzt und `$data->json` nicht leer) wird `boactions` aus dem mitgelieferten `$data->json` extrahiert; sonst wird der gespeicherte Wert via `booking_option::get_value_of_json_by_key($data->id, 'boactions')` aus der DB gelesen. Setzt zusaetzlich `$data->boactionsjson = json_encode($data->boactions ?? [])` fuer den Form-Workflow. **Seiteneffekte:** mutiert `$data`; im Nicht-Import-Pfad ein DB-Read pro Aufruf (`get_value_of_json_by_key`, @throws `dml_exception`). **Rueckgabe:** `void`. **Bewertung:** B — die Verzweigung Import vs. Normal ist sinnvoll; `$settings` wird nicht genutzt, obwohl die Settings die `boactions` bereits cachen koennten — `get_value_of_json_by_key($data->id, ...)` macht stattdessen einen frischen DB-Zugriff. Bei zeilenweisem/listenartigem Aufruf (z.B. Kopieren vieler Optionen) waere das ein potenzieller N+1-Punkt; im Einzel-Form-Kontext unkritisch.

### Triviale Properties
Sechs statische Konfig-Properties als Field-API-Metadaten: `$id = MOD_BOOKING_OPTION_FIELD_ACTIONS` (Z.48), `$save = MOD_BOOKING_EXECUTION_POSTSAVE` (Z.56), `$header = MOD_BOOKING_HEADER_ACTIONS` (Z.62), `$fieldcategories = [MOD_BOOKING_OPTION_FIELD_STANDARD]` (Z.68), `$alternativeimportidentifiers = []` (Z.74), `$incompatiblefields = []` (Z.80).

## Bewertungs-Resümee
Solide, schlanke Field-Adapter-Klasse: keine eigene Persistenz, sauberer JSON-on-option-Ansatz, klare Trennung von Save/Form/Set-data. Schwaechen sind defensiver Natur: `json_decode` ohne Fehlerpruefung in `prepare_save_field`, ungenutztes `$settings` und ein potenzieller DB-Read-pro-Zeile in `set_data` (kein N+1 in den derzeitigen Aufrufpfaden, aber latent). Funktional korrekt. Klassen-Score **B / P3**.
